# 販売版（完全非対面トラック）

受注と並行して進める、**人とやりとりせずに売れる形**。

`toolkit/` はそのまま製品にできる。受注案件で作った設定ファイルが、
そのまま販売版のテンプレート集になる — 二重に働かなくてよいのが並行する理由。

---

## 何を売るか

**製品名（仮）: サイト新着ウォッチャー**

「指定したサイトの新着を、条件つきで自動通知するツール」の**汎用版**。
受注案件との違いは、**設定を顧客自身が書く**こと。だからサポートが要らない。

| | 受注版 | 販売版 |
|---|---|---|
| 設定 | こちらが書く | 購入者が書く（テンプレ同梱） |
| 対象サイト | 顧客専用 | 汎用 |
| サポート | あり | なし（「サポートなし」と明記） |
| 価格 | ¥15,000〜 | **¥2,500〜3,500** |
| 手間 | 案件ごとに発生 | 一度作れば増えない |

## 販売版に必要な作業

受注版との差分だけ。ゼロから作るものはない。

1. **設定ウィザードの追加**
   購入者はJSONを書けない。ダッシュボードの設定タブに
   「URLを入れる → 取りたい要素をクリックで選ぶ」形の簡易ウィザードを足す。
   **ここが売れるかどうかの分かれ目。** JSONを書かせる製品は返品と質問の温床になる。

2. **サンプル設定集**
   受注案件で作った config を、匿名化して同梱する。
   「求人サイト用」「入札公告用」「RSS用」など。**受注をこなすほど厚くなる資産。**

3. **説明書（PDF）**
   受注案件の納品書がそのまま使える。

4. **ライセンス文**
   「個人・法人での業務利用可。再配布・再販売は不可。サポートなし。
   　対象サイトの利用規約の遵守は購入者の責任。」
   最後の1文は必須。規約違反の使い方をされたときの線引きになる。

5. **無料版を作る**
   収集元1つまで・通知はCSVのみ、の制限版を無料配布する。
   BOOTHでは無料版のダウンロード数がそのまま有料版への導線になる。

## 売り方（集客）

完全非対面のコストは「集客を自分でやる」こと。ここを甘く見ると1本も売れない。

- **X（Twitter）で製作過程を出す。** 動いている画面のGIFが一番強い。
- **note に「◯◯を自動化した」記事を書き、末尾に製品リンクを置く。**
  検索流入が長く効く。受注案件で得た知見（規約の話、robots.txtの話）は記事になる。
- **無料版を配って母数を作る。**

## 収益の見立て（正直な数字）

| | 楽観 | 現実的 |
|---|---|---|
| 月間販売数 | 20本 | **3〜8本** |
| 単価 | ¥3,000 | ¥3,000 |
| 手数料引後 | ¥56,000 | **¥8,000〜22,000** |

**販売版だけで月数万円は難しい。** 立ち上がりに数ヶ月かかり、集客が効き始めるまで
ほぼゼロが続く。だから**受注で現金を作りながら、販売版は積み上げていく**という
並行のしかたになる。

順番を間違えないこと。**受注が先、販売版は後。** 逆にすると無収入期間が長引き、
資金15万円が削られる。

## 進める順番

1. 受注トラックを走らせる（出品 → 初回受注 → 納品 → 保守化）
2. 受注で溜まった config をテンプレ化
3. 設定ウィザードを実装
4. 無料版を BOOTH に出す
5. 有料版を出す + note 記事を書く

**3以降に着手するのは、受注で初回入金が確認できてから。**
